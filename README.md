# 局域网快传 v5.4

## 本次更新（v5.4）：局域网中继自动发现（免手输 IP）

### 中继端：双通道广播自己
- **mDNS**：以 `_lanshare._tcp.local` 发布服务，TXT 携带 `name / version / port / secure`
  手写 DNS 报文解析与构造（仅用 Node 内置 `dgram` + `os`），**保持零依赖**
- **UDP 广播**：每 3 秒向 `255.255.255.255:41234` 发信标 JSON，穿透性优于组播，为 mDNS 兜底
- 服务名默认取主机名，可用 `--name 书房电脑` 自定义；`--discover-port` 改广播端口
- `--no-discover` 可完全关闭；Ctrl+C 时随进程优雅释放
- 广播包带随机 `id`，接收端据此忽略自己发出的包
- 5353 被系统 Bonjour 占用时自动降级，仅用 UDP 广播，不影响主功能

### 安卓端：一键发现
- 新增 `RelayDiscovery`：NsdManager 搜 mDNS + UDP 监听广播，双通道并行
- 配置界面新增「🔍 发现局域网中继」，约 5 秒列出：服务名 / IP:端口 / 来源 / 版本
- 选中后回填地址并重新打开配置框，可继续调整频道再保存
- 补齐权限：`CHANGE_WIFI_MULTICAST_STATE`、`ACCESS_WIFI_STATE`、`ACCESS_NETWORK_STATE`
  、`NEARBY_WIFI_DEVICES`（`neverForLocation`，Android 13+ 起）
- 获取组播锁并在结束/销毁时释放；NsdManager 串行解析（并发 resolve 会被系统拒绝）

### 浏览器扩展端
- 本版无功能改动，仅版本号同步为 `5.4.0`。
  原因：扩展页无 mDNS API，且 `chrome-extension://` 拿不到本机 IP，无法判断网段；
  为 UDP 监听申请 `sockets` 权限属过宽授权，得不偿失。仍为手动填址 + 记住历史。

### 验证
- 新增 `relay/test-discovery.js`，真实启动中继并发真实查询包：**22/22 通过**
  - mDNS：PTR 应答、实例名、SRV 端口、TXT 字段、A 记录、无关查询不应答、SRV 显式查询
  - UDP：信标 JSON 结构、服务名、端口、版本、`id`、候选 IP 列表
- 既有测试无回归：冒烟全通过（含 200KB 大文件无损）、待投递 11/11

### 未发现中继时的排查
1. 电脑中继已启动（`http://电脑IP:8080/health` 应显示 `LAN Text Relay v5.4 OK`）
2. 手机与电脑在同一局域网（部分路由器的「AP 隔离」会阻断）
3. 电脑防火墙未拦截 UDP 5353（mDNS）与 41234（广播）
4. 企业/公共网络常抑制组播 —— 此时靠 UDP 广播通道仍可发现


电脑（浏览器扩展）↔ 手机（Android App）在同一局域网内互传文本、图片与任意格式文件。

## 历史更新（v5.3）：两端界面统一

**目标**：扩展端与安卓端共用同一套显示规范 —— 同样的消息结构、同样的尺寸比例、
同样的图片横竖规则，两端观感一致。

### 尺寸基准：全部按「界面宽度」换算

两端都以界面宽度为唯一基准，比例完全相同（扩展端 UI_W = 300px，安卓端 = 屏幕宽度）：

| 项目 | 比例 | 扩展端（界面 300px） | 安卓端（屏幕宽 W） |
|------|------|---------------------|-------------------|
| 弹窗尺寸 | 高 600、宽 = 高/2 | 300 × 600 | — |
| 头像边长 | 界面 1/15 | 20px | W/15 |
| 横图（宽 ≥ 高） | 以宽为准 | 150px | W/2 |
| 竖图（宽 < 高） | 以高为准 | 67.5px | W × 9/40 |
| 文件卡片 | 宽 1/2、高 1/10 | 150 × 30px | W/2 × W/10 |

### 消息结构

每条消息 = **方形头像 + 内容列**，内容列自上而下是「发送者 → 消息体 → 时间」：

- **头像**：色块 + 设备名首字符，底色由设备名经 djb2 哈希派生；
  两端同算法，同一设备在任何端都是同一个颜色。自己发的消息头像排到外侧（右侧）。
- **发送者**：一律显示（含自己），多端互发时可区分来源；他人蓝、自己绿。
- **消息体**：文字 → 带气泡（内边距收紧，更紧凑）；图片 → **不带气泡**，直接显示；
  文件 → 固定尺寸卡片，卡片自带背景。

### 图片

- 横图以宽为准、竖图以高为准，另一边按原图比例自适应，**不做任何裁切**。
- 组内图片与单张同一套规则（此前组内是「定高 + cover」，任何比例都被切成一条）。
- 折叠时第三张露上半截，高度按该图实际高度的一半精确计算 ——
  横图与竖图的高度并不相同，写死数值必然有偏差。

### 图片放大

- 放大后**不再显示关闭按钮**，点击画面即可关闭（两端一致）。

### 清理

- 删除 4 个已无引用的 drawable：`bg_bubble_batch_me/other`（图片组不再套气泡）、
  `ic_close`、`bg_dark_transparent`（关闭按钮已移除）。
- 删除 4 个中继测试残留数据目录 `relay/.test-*-data/`。

## 历史更新（v5.1）：提醒归位、图片展示改版、清理冗余

**目标**：提醒只在浏览器内出现；手机通知合并成一条；图片按屏幕一半宽度完整显示，
全屏查看改为左右滑动翻阅本聊天的图片。

### 提醒

- **浏览器扩展**：消息提醒只做「扩展图标角标 + 弹窗内一闪而过的轻提示」，
  全程不调用 `chrome.notifications`，因此不会产生系统通知。
  （若仍看到系统通知，通常是旧版扩展未重新加载，或 Chrome 的**下载完成**气泡，
  后者是浏览器自身行为，可在设置里关掉自动下载。）
- **安卓端**：新消息通知**合并为一条**——2.5 秒内的多条累积后用固定 ID 覆盖更新，
  标题显示「N 条新消息」，展开可看最近 6 条；进入 App 自动清除。
  此前每条消息各发一个通知（ID 递增），连续收图时通知栏会被刷满。

### 图片展示（安卓端）

- **宽度改为屏幕一半**（此前固定 230dp），高度按原图比例自适应。
- **组内图片完整显示**：此前组内图片是「定高 140dp + CENTER_CROP」，
  任何比例都会被裁成一条——这正是「每张只显示一部分」的原因。
  现改为按原比例完整渲染；折叠时第三张仍只露上半截，但那是外层容器裁切，
  图片本身不变形。
- **全屏查看改为左右滑动切换**：单指左右滑翻阅本频道的前后图片，
  单指点击关闭，底部显示「3 / 8 · 左右滑动切换」。
  去掉了原先的单指拖动平移（图片已完整显示，不再需要拖动）。
- 不再预先解码 Bitmap，改由 Glide 按需加载（本机留底 > 中继直链 > 内联 base64），
  同时只驻留当前一张，避免多图时 OOM。

### 清理

- 删除测试数据 `.relay-data/`、`relay/.relay-data/`、`relay/.test-relay-data/`。
- 删除 `activity_share.xml`（分享入口已改为无界面，直接在后台发送，不再需要布局）。
- 修正 `relay/test-file.js` 中已过时的「历史补发」断言（v4.9 起中继不再回显历史）。

## 历史更新（v4.9）：去掉服务端历史回显，改为「10 秒待投递」

**目标**：客户端只依赖自身的本地存储；同时对端短暂离线时，只要在 10 秒内回来就能补收到消息。

### 中继端

1. **移除服务端历史持久化与加入时回显**
   - 删除 `history.json`、`appendHistory()`、`buildBackfill()`，以及 HTTP `/history` 端点。
   - 加入频道时不再下发 `action:'history'`，客户端不再从中继补历史。
   - 频道口令（`channels.json`）与引用式文件存储继续保留。

2. **新增「待投递队列」（纯内存，不落盘）**
   - 每条广播消息都会暂存 `PENDING_TTL`（默认 **10000ms**，可用 `--pending-ttl` 调整）。
   - 客户端加入频道时，补发它**尚未收到**、且仍在存活期内的消息。
   - 过期即弃，绝不作为历史存储。
   - 每 2 秒清理一次过期条目；每频道最多缓存 `PENDING_KEEP`（默认 100）条。

3. **入队不依赖「对端是否在线」的判定**
   - 实测发现：对端进程被强杀时，服务端可能收不到 `close` 事件，留下"幽灵连接"，
     若按「是否有人在线」来决定是否暂存，会误判为已送达而漏投。
   - 因此改为**始终入队** + 记录真正写出的连接；重复补投由客户端按消息 ID 去重。
   - 同时 `sendTo` 写出失败会主动断开连接，加速幽灵连接回收。

### 客户端

- **浏览器扩展**：删除 `mergeHistory()` 与服务端 `history` 消息处理；
  本地历史仍存 `chrome.storage.local`，重开浏览器不丢。
- **安卓端**：删除 `parseHistoryEntry()`、历史监听与注册/注销代码。

**校验**

- 新增 `relay/test-pending.js`：**10/10 通过**
  （存活期内补收、不重复补投、过期不补投、无 history 回显、`/history` 已移除、健康检查）。
- `relay/test-source.js`：**9/9 通过**（待投递同样透传 `source=share`）。
- `relay/test-relay-smoke.js`：全部通过（含 200KB 大文件经 127 长度编码无损）。
- 扩展端 4 个 JS、中继 JS：`node --check` 通过。

### v4.8
- **修复「手机分享的图片/文件，电脑端不自动下载」——根因在中继端**
  安卓「系统分享」发出的消息带 `source="share"`，但中继 `handleMessage`
  **从未解析该字段**，广播与历史存储时都把它丢弃，导致接收端
  `record.source` 恒为空，`if (record.source === 'share')` 永远不成立。
  已在中继的「解析 → 广播 → 历史存储」三处补齐透传。
  （此前几轮一直在浏览器端与安卓端排查，唯独漏了中继这个中间环节。）
- 回归测试 `relay/test-source.js` **9/9 通过**：外置(fileId)、内联(data)、
  历史补发三条路径均正确透传 source，且无标记的普通消息不会凭空带上 source。
- 下载链路可靠性：`downloadImage` / `downloadFile` 改为 `await saveDataUrl`，
  确保 offscreen 落盘真正发起后再回报「已下载」。
